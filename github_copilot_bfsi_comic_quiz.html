SCENE 1

The ₹1 Mystery

Surface · Copilot in the IDE

🎬 Your move: Ravi is already inside the code, writing and testing. Where should he use GitHub Copilot to fix the rounding bug?

When you're hands-on in code, the IDE is home. Copilot sees your open files and helps you without switching context.

  • Copilot in the IDE gives code completions, Chat and agent mode right where you write, test and debug. It's the best fit for focused, hands-on fixes.
  • Banking tip: ask Copilot to "add a unit test that compares the EMI to the sanction-letter value for 3 sample loans". Money logic needs tests, not just a fix.
  • A adds copy-paste and context switching. C changes production directly and skips review, which breaks change-control rules. D is overkill for one small fix.

▶ Fixed and tested! Then the stand-up brings more tickets...

SCENE 2

Where Are My Tickets?

GitHub MCP server · Pulling issues

🎬 Your move: Ravi wants Copilot in VS Code to list his open loan-calc issues and start on them, without juggling browser tabs. What should he do?

The GitHub MCP server gives Copilot in VS Code live GitHub tools: issues, pull requests, comments and more.

  • MCP (Model Context Protocol) connects Copilot to external tools. With the GitHub MCP server, agent mode can search, read and summarise issues and PRs on your behalf.
  • Simple prompts that work: "Show my open issues", "Summarise the comments on #107", "Which PRs are waiting for my review?". Sign in with your own GitHub account so Copilot sees only what you can see.
  • A is slow and error-prone. B invents work. D is stale by lunchtime and leaks ticket data into the code repository.

▶ Three bugs down. Then, while testing, Ravi spots something odd...

SCENE 3

Not My Code!

GitHub MCP server · Creating issues

🎬 Your move: The bug is in another team's repository. What's the best way for Ravi to report it from VS Code?

The GitHub MCP server can write as well as read: create issues, add comments, open PRs, always with your approval.

  • Copilot drafts a clear, well-structured issue in the right repository, and VS Code asks you to confirm before the tool runs.
  • Bank-safe habit: use test data only. Never put real customer names, policy numbers or Aadhaar/PAN details in an issue.
  • B bypasses the other team's ownership and reviews. C and D leave no trackable record, which auditors won't like.

▶ Issue logged. That night, Meera's pager goes off...

SCENE 4

The 2 AM Batch Job

Surface · GitHub Copilot CLI

🎬 Your move: Meera works entirely in the terminal. How can she get Copilot to help her find and fix the batch script error?

Copilot CLI brings an agent right into the terminal, where platform and ops engineers already work.

  • Copilot CLI can read files, explain errors, suggest and run shell commands, and edit scripts, asking for your permission before it takes actions.
  • Bank-safe habit: fix the script on a branch, raise a PR and follow change management. Don't hot-patch production at 2 AM unless it's an approved emergency change.
  • A leaks customer data. B is slow and changes a controlled server. C delays customer statements when help is available now.

▶ Statements went out on time. On Tuesday morning, Aisha has a review to do...

SCENE 5

The Non-Coder's Review

Surface · Copilot on GitHub.com

🎬 Your move: Aisha only uses her browser. How can she quickly understand PR #318 before approving it?

Copilot on GitHub.com works right where PRs, issues and repositories live, with no IDE needed.

  • On GitHub.com, Copilot can summarise pull requests, explain code and answer questions about issues and repositories, all in the browser.
  • Good follow-ups: "Which business rules changed?" and "Are there tests for the new approval limit?". Then leave review comments in the PR so there's an audit trail.
  • A is heavy for a non-coder. C adds a hand-off. D skips the review that controls require.

▶ Aisha approved it with confidence. On Wednesday, Tom is drowning...

SCENE 6

Three Fires, One Lead

Surface · GitHub Copilot app

🎬 Your move: Tom wants to run three separate pieces of work across three repositories in parallel, each kept isolated, and track them all in one place. What fits best?

The GitHub Copilot app is a desktop home for running and steering several agent sessions in parallel.

  • Each session in the Copilot app runs in its own git worktree and branch, so parallel tasks don't step on each other. Sessions can start from an issue, a PR or a prompt.
  • Admin note for banks: on Copilot Business or Enterprise, the organisation admin must enable the Copilot CLI policy before the app can be used.
  • A and B mix three changes together. D explains code but doesn't run the work.

▶ On Thursday, back in VS Code, Ravi has a big refactor and a meeting in 15 minutes...

SCENE 7

Don't Close That Window!

Harness · Local vs Copilot vs Cloud

🎬 Your move: The refactor needs Ravi's local, uncommitted changes, and it must keep running in the background, even if he closes this editor window. Which option should he pick?

The Copilot harness is the recommended default for day-to-day agent work, and it keeps running after you close the editor window.

  • Copilot harness sessions run in the Agent Host, separate from the editor window. Keep the VS Code application running (closing a window isn't the same as quitting the app).
  • Local sessions are tied to the editor window: closing it stops the work. Microsoft has also marked the Local harness as deprecated, so move to the Copilot harness.
  • C: Cloud uses its own workspace, not your local editor state, so it can't see uncommitted changes. D: changing the model never changes the harness.

▶ The refactor finished during the meeting. Now it's Friday evening...

SCENE 8

The Friday Hand-off

Harness · Cloud (Copilot cloud agent)

🎬 Your move: The task is well scoped, the code is on GitHub, and Ravi's laptop will be off all weekend. How should the work get done?

Cloud is for well-scoped work you can fully hand off, with no need to keep your machine on.

  • Cloud agents run on GitHub infrastructure, create a pull request, push commits as they work, and leave the result ready for review. Progress shows on GitHub.com.
  • Bank-safe habit: the PR still goes through branch protection, required reviewers and CI, so a human approves before anything is merged. Keep secrets out of issues and prompts.
  • A, B and C all depend on Ravi's machine staying on and awake.

▶ Monday is release day...
